# 출근 브리핑

## 0. 준비 확인

- `subway` MCP 의 `get_subway_arrival` 도구가 보여야 한다. 안 보이면 `SEOUL_API_KEY` 환경변수 설정과 Claude Code 재시작을 안내하고 멈춘다.
- 카카오톡은 claude.ai 에 연결한 PlayMCP 커넥터의 `KakaotalkChat-MemoChat` 을 쓴다. **사용자가 보내 달라고 할 때만** 보낸다.

## 1. 입력 정리

- 출발역 (필수). 없으면 한 번만 묻는다.
- 도착해야 하는 시각, 역까지 걸어가는 분 (선택). 없으면 도착 시각 판단은 생략하고 도착 순서만 알린다.

## 2. 데이터

1. `get_subway_arrival` 로 출발역을 조회한다.
2. 응답의 `updated` 시각을 **기준 시각**으로 적는다.

규칙:

- 숫자는 **도구 결과에서 읽은 것만** 쓴다. 추정으로 채우지 않는다.
- `seconds` 는 `updated` 시점 기준이다. 지금 기준 남은 시간은 `seconds - age_seconds` 로 계산하고, 0 이하이면 이미 도착했거나 출발한 열차로 본다.
- `seconds` 가 없으면 `message` 문구를 그대로 쓰고 분 단위는 적지 않는다.
- 도구가 오류를 돌려주면 그 메시지를 그대로 알리고 멈춘다. 지어내지 않는다.

## 3. 판단

도착 목록과 사용자 조건을 `route-advisor` 에이전트에 넘겨 추천 1~2개를 받는다.
걸어가는 시간이 도착 시간보다 길면 그 열차는 「놓침」으로 본다.

## 4. 터미널에 보여 주기

```
[출근 브리핑] 14:05 기준
- 강남 2호선 성수 방면: 3분 후
- 걸어서 4분이면 다음 열차 권장
출처: 서울 열린데이터광장
```

## 5. 카카오톡 나챗방으로 보내기 (요청 시에만)

- 같은 내용을 `KakaotalkChat-MemoChat` 으로 **한 번** 보낸다.
- 첫 줄은 `[출근 브리핑]` 으로 시작하고 `기준` 시각을 넣는다 (Hook 이 이 줄로 알아본다).
- **200자 이내.**

## 하지 말 것

- API 키를 출력하거나 메시지에 넣지 않는다. Hook 이 막는다.
- 실시간 정보라 열차 지연·누락이 있을 수 있다. 도착 보장처럼 말하지 않는다.
